# astrbot_plugin_hentai_collector

AstrBot 本子与里番聚合插件。一个插件接入 **E-Hentai / ExHentai、nhentai、JMComic（禁漫天堂）、哔咔漫画、Hanime1** 五个源站，提供：

- **链接解析**：直接发送作品链接或 `JM123456`，自动回复封面与作品信息，并下载打包为 **PDF / ZIP** 发送（里番发送视频）。
- **聚合与单站指令**：`搜本子` 同时搜索全部本子源站、按源站分组以嵌套合并转发返回；`搜eh`、`搜jm` 等只查一个站。结果附带带序号的封面拼图，按序号获取作品。
- **排行榜**：日榜 / 周榜 / 月榜 / 年榜 / 总榜（以源站实际提供为准）。
- **随机作品**：从全部源站随机（混合或每站各随机，可配置），或限定站点、关键词、分类等条件随机。
- **自动推送**：定时推送排行榜、条件作品（追更）、随机作品到群聊或私聊，自动去重。
- **缓存复用**：保留期内重复请求同一作品直接发送已生成的文件。

> 本插件涉及成人内容，请仅在合法、成年且已获得同意的环境中使用，并通过权限控制限制可用的群和用户。

## 安装

在 AstrBot 插件市场搜索安装，或将本仓库放入 `data/plugins/` 后重启 AstrBot。依赖见 `requirements.txt`（`aiohttp`、`curl_cffi`、`jmcomic`、`pillow`），AstrBot 会自动安装。

国内网络访问 E-Hentai、nhentai、Hanime1、哔咔通常需要代理：在配置 **网络设置 → 代理地址** 填写，例如 `http://127.0.0.1:7890`。

### Docker 部署

插件发送的 PDF / 视频是本地文件，**消息平台（如 NapCat）必须能读到同一路径**：

1. 让 AstrBot 与 NapCat 容器挂载同一个宿主机目录，例如都挂载到 `/app/sharedFolder`；
2. 配置 **缓存设置 → 缓存目录** 留空时默认使用 `/app/sharedFolder/astrbot_plugin_hentai_collector/cache`，也可填写其他共享路径。

## 支持的源站

| 源站 | 链接解析 | 搜索 | 排行榜 | 随机 | 输出 | 备注 |
|------|----------|------|--------|------|------|------|
| E-Hentai / ExHentai | `e-hentai.org/g/…` / `exhentai.org/g/…` | ✓（支持标签语法、评分、页数、分类） | 日 / 月 / 年 / 总 | ✓ | PDF / ZIP | 里站需要 Cookie |
| nhentai | `nhentai.net/g/ID` | ✓（支持站内搜索语法、页数） | 日 / 周 / 月 / 总 | ✓ | PDF / ZIP | 可设置语言过滤 |
| JMComic | `18comic.vip/album/ID`、`JM123456` | ✓（排序、分类） | 日 / 周 / 月 / 总 | ✓ | PDF / ZIP | 自动还原切割图片 |
| 哔咔漫画 | 仅支持 ID（`看哔咔 <24位ID>`） | ✓（排序、分类） | 日 / 周 / 月 | ✓ | PDF / ZIP | 需要账号，默认关闭 |
| Hanime1 | `hanime1.me/watch?v=ID` | ✓（类型、排序） | 日 / 周 / 月 / 总 | ✓ | 视频 / 文件 / 链接 | 未登录通常只有 480P |

## 指令

插件没有“默认源站”：**不写站点的指令查询全部已启用源站**，**带站点标识的指令只查该站**。

### 聚合指令

| 指令 | 别名 | 说明 |
|------|------|------|
| `搜本子 关键词 [条件]` | `搜本` | 同时搜索全部本子源站，每站显示“聚合列表每站最多显示条数”条 |
| `排行本子 [日榜\|周榜\|月榜\|年榜\|总榜] [页码]` | `本子排行`、`排行榜` | 全部本子源站的排行榜；不写榜单时各站用默认榜单（周榜，没有周榜的站用其第一个榜单），写了榜单时跳过不支持该榜单的站 |
| `随机本子 [条件] [N本]` | `随机本` | 按“聚合随机方式”从候选源站随机，最多 5 本（每站随机时为每站最多 5 本） |
| `搜里番` / `排行里番` / `随机里番` | `里番排行` | 同上，查询里番源站（目前为 Hanime1） |

聚合结果以**嵌套合并转发**发送：第一条为总览（各站序号范围、失败原因），之后每个源站一组（标题、封面拼图、作品条目）。单站与聚合列表均将每部作品放在独立的转发消息中，标题、统计、分类、作者与发布时间分行展示；普通消息按作品分块留白。序号在各站之间连续，`看本 12` 即取总览中第 12 部。协议端不支持嵌套时自动改用单层合并转发，也可在配置中关闭嵌套。

封面拼图跳过下载失败、损坏或空白的图片，保留作品在文字列表中的原序号；例如第 2 张封面失败，拼图中的编号为 1、3，仍可用 `看本 2` 获取该作品。该站没有可用封面时只展示文字列表。

### 单站指令

把“本子 / 里番”换成站点标识：

| 源站 | 标识 | 指令 |
|------|------|------|
| E-Hentai | `eh`（`ex`） | `搜eh`、`排行eh`、`随机eh`、`看eh`、`详情eh` |
| nhentai | `nh` | `搜nh`、`排行nh`、`随机nh`、`看nh`、`详情nh` |
| JMComic | `jm`（`禁漫`） | `搜jm`、`排行jm`、`随机jm`、`看jm`、`详情jm` |
| 哔咔 | `哔咔`（`pica`、`bika`） | `搜哔咔`、`排行哔咔`、`随机哔咔`、`看哔咔`、`详情哔咔` |
| Hanime1 | `anime`（`hanime`、`h1`） | `搜anime`、`排行anime`、`随机anime`、`看anime`、`详情anime` |

参数与聚合指令相同；`看<标识> ID|链接` 下载并发送文件，`详情<标识> ID|链接` 只看作品信息，例如 `看jm 350234`、`详情nh 177013`。

### 通用指令

| 指令 | 别名 | 说明 |
|------|------|------|
| `本子帮助` | `hc` | 查看帮助、站点标识与已启用源站 |
| `看本 序号\|链接` | `本子下载`、`看里番` | 按最近列表的序号或作品链接 / `JM123456` 直接下载并发送文件 |
| `本子详情 序号\|链接` | `详情` | 只看作品信息 |
| `翻页 页码\|下一页\|上一页` | `本子翻页` | 翻阅最近一次列表（聚合列表各站一起翻页） |
| `本子会话` | | 查看当前会话 ID（用于推送目标） |
| `本子推送 [执行 序号]` | | 查看 / 手动执行推送任务（管理员） |
| `本子清理缓存` | | 清理全部已生成文件（管理员） |

指令名可以在 AstrBot WebUI 的指令管理中重命名或禁用。

`看本`、`看eh`、`看jm` 等下载指令直接发送文件；查看封面与作品信息请用 `本子详情` 或对应站点的详情指令。下载与打包进度默认关闭，可在“基础设置 → 发送进度提示”中开启；下载失败、缺页、页数限制提醒和仅链接模式的视频地址仍会发送。已有配置若保存为开启，需要在配置页手动关闭。

### 条件写法

| 写法 | 含义 | 生效源站 |
|------|------|----------|
| `p2`、`第2页`、`页码=2` | 页码 | 全部 |
| `排序=最新\|热门\|观看\|点赞` | 排序 | nhentai、JM、哔咔、Hanime1 |
| `评分=4` | 最低评分（2-5） | E-Hentai |
| `页数=20` | 最少页数 | E-Hentai、nhentai |
| `分类=同人志` | 分类 / 类型 | 全部（取值见下） |
| `-ntr` | 排除关键词 | 全部 |
| `3本` | 随机数量 | 随机指令 |

分类取值：E-Hentai 为 `同人志 / 漫画 / 画师CG / 游戏CG / 图集 / Cosplay / 西方 / 非H / 杂项`（也可写英文名）；JM 为 `同人 / 单本 / 短篇 / 韩漫 / 美漫 / cosplay / 3d / 其他`；Hanime1 为 `裏番 / 泡麵番 / 3DCG / Motion Anime / 2.5D / 2D動畫 / MMD / Cosplay`；哔咔为站内分类名；nhentai 为 `doujinshi / manga`。

## 配置说明

所有配置都在 AstrBot WebUI 的插件配置页完成，分组如下（详见 [配置说明](docs/CONFIG.md)）：

- **基础设置**：自动解析、JM 编号识别、解析后动作（发送文件 / 仅信息）、进度提示。
- **源站开关**：逐个启用源站。
- **网络设置**：代理、超时、重试、图片并发。
- **各源站设置**：ExHentai Cookie、nhentai 语言过滤、JM 域名、哔咔账号、Hanime1 清晰度与发送方式。
- **文件输出**：PDF / ZIP / 两者，单 PDF 页数、图片质量与宽度、单本最大页数。
- **消息展示**：封面、封面模糊、列表拼图、合并转发与嵌套合并转发、单站 / 聚合列表条数、标签数。
- **随机设置**：随机后是否直接发送文件、聚合随机方式（混合随机 / 每站随机）、随机候选源站。
- **自动推送**：推送任务（排行榜 / 条件作品 / 随机作品）。
- **权限控制 / 缓存设置 / 使用限制**。

### 自动推送

在 **自动推送 → 推送任务** 点击添加，选择模板：

- **排行榜推送**：如“每天 09:00 推送 E-Hentai 日榜前 5”。
- **条件作品推送**：如“每天 20:00 搜索 `artist:xxx` 的最新作品”，开启“跳过已推送的作品”即为追更。
- **随机作品推送**：如“每天 12:00 随机 1 部”。

推送目标可填 **群号 / 用户 QQ**（使用“推送平台 ID”或自动选择的 QQ 平台），也可在目标会话发送 `本子会话` 获取会话 ID 填入“推送会话 ID”。配置完成后管理员发送 `本子推送 执行 1` 立即测试。

## 注意事项

- **E-Hentai** 请求过快会被临时封禁 IP，图片额度用尽会返回 509；遇到时请降低并发或稍后再试。
- **哔咔** 所有接口都需要登录，建议使用小号。
- **Hanime1** 视频较大，QQ 对视频 / 文件有大小限制；建议设置“视频大小上限”，或改用“文件”“仅链接”。
- 单站列表每页最多显示“单站列表最多显示条数”条，聚合列表每站最多显示“聚合列表每站最多显示条数”条；翻页按源站分页进行。
- 聚合指令需要等待所有源站返回（单站最长 90 秒），某个站失败或超时只在总览中标注，不影响其他站。
- 合并转发仅在 QQ 个人号协议端（aiocqhttp）生效，其余平台逐条发送。嵌套合并转发显示异常时可关闭“聚合结果使用嵌套合并转发”。
- 已生成文件默认保留 24 小时供重复请求复用，可在“缓存设置”调整。
