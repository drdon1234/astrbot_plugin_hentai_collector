# astrbot_plugin_hentai_collector

AstrBot 本子与里番聚合插件。一个插件接入 **E-Hentai / ExHentai、nhentai、JMComic（禁漫天堂）、哔咔漫画、Hanime1** 五个源站，提供：

- **链接解析**：直接发送作品链接或 `JM123456`，自动回复封面与作品信息，并下载打包为 **PDF / ZIP** 发送（里番发送视频）。
- **聚合与单站指令**：`搜本子` 同时搜索全部本子源站、按源站分组以嵌套合并转发返回；`搜eh`、`搜jm` 等只查一个站。结果附带带序号的封面拼图，按序号获取作品。
- **排行榜**：日榜 / 周榜 / 月榜 / 年榜 / 总榜（以源站实际提供为准）。
- **随机作品**：从全部源站随机（混合或每站各随机，可配置），或限定站点、关键词、分类等条件随机。
- **自动推送**：定时推送排行榜、条件作品（追更）、随机作品到群聊或私聊，自动去重。
- **多触发词**：每个操作可配置多个触发词，帮助与结果提示使用当前可用的指令名称。
- **缓存复用**：保留期内复用完整文件；遇到下载缺页，再次发送同一获取指令会重新下载。

> 本插件涉及成人内容，请仅在合法、成年且已获得同意的环境中使用，并通过权限控制限制可用的群和用户。

## 安装

需要 **AstrBot 4.28.2 或更新的 4.x 版本**。在插件市场搜索安装，或将本仓库放入 `data/plugins/` 后重启 AstrBot。依赖见 `requirements.txt`（`aiohttp`、`curl_cffi`、`jmcomic`、`pillow`），AstrBot 会自动安装。

国内网络访问 E-Hentai、nhentai、Hanime1、哔咔通常需要代理：在配置 **网络设置 → 代理地址** 填写，例如 `http://127.0.0.1:7890`。

### Docker 部署

插件发送的 PDF / 视频是本地文件，**消息平台（如 NapCat）必须能读到同一路径**：

1. 让 AstrBot 与 NapCat 容器挂载同一个宿主机目录，例如都挂载到 `/app/sharedFolder`；
2. 配置 **缓存设置 → 缓存目录** 留空时默认使用 `/app/sharedFolder/astrbot_plugin_hentai_collector/cache`，也可填写其他共享路径。

## 指令

下文使用默认触发词。管理员可在 **指令触发词** 配置每个操作的多个名称，第一项用于帮助和提示；自定义后请以实际帮助和卡片上的指令为准。AstrBot WebUI 指令管理中已保存的改名、别名和禁用设置优先。

插件没有“默认源站”：**不写站点的指令查询全部已启用源站**，**带站点标识的指令只查该站**。

### 第一次使用

1. 发送 `本子帮助` 查看当前可用的指令和源站，再发送 `搜本子 原神` 或 `搜里番 关键词`。
2. 收到带序号的列表后，发送 `本子详情 1` 先看介绍，或发送 `看本 1` 下载第一部；下一页用 `翻页`，返回上一页用 `翻页 上一页`。
3. 收到随机作品、链接解析或定时推送的卡片后，复制卡片中的获取指令，例如 `看jm 350234`。

**序号只对应本人在当前聊天中最近一次搜索或排行列表，默认有效 30 分钟。** 群友的列表、其他聊天中的列表以及随机、解析、推送卡片不能直接套用这个序号。重新搜索、查看排行榜或成功翻页会更新序号；新查询成功但没有匹配结果时，发送空结果提示后才清除旧序号。查询全部失败、翻页失败或通知发送失败时保留上一份可见列表。列表仍在展示时发送序号，会等待展示完成后再选取；选定作品后的下载不阻塞新的列表查询。

### 聚合指令

| 指令 | 别名 | 说明 |
|------|------|------|
| `搜本子 关键词 [条件]` | `搜本` | 同时搜索全部本子源站，每站显示“聚合列表每站最多显示条数”条 |
| `排行本子 [日榜\|周榜\|月榜\|年榜\|总榜] [页码]` | `本子排行`、`排行榜` | 全部本子源站的排行榜；不写榜单时各站用默认榜单（周榜，没有周榜的站用其第一个榜单），写了榜单时跳过不支持该榜单的站 |
| `随机本子 [条件] [N本]` | `随机本` | 按“聚合随机方式”从候选源站随机，最多 5 本（每站随机时为每站最多 5 本） |
| `搜里番` / `排行里番` / `随机里番` | `里番排行` | 同上，查询里番源站（目前为 Hanime1） |

聚合结果以**嵌套合并转发**发送：第一条为总览（各站序号范围、失败原因），之后每个源站一组（标题、封面拼图、作品条目）。单站与聚合列表均将每部作品放在独立的转发消息中，标题、统计、分类、作者与发布时间分行展示；普通消息按作品分块留白。序号在各站之间连续，`看本 12` 即取总览中第 12 部。列表会提示详情、下载、可用的上一页和下一页，以及序号有效期；没有下一页时明确提示最后一页。协议端不支持嵌套时自动改用单层合并转发，也可在配置中关闭嵌套。

封面拼图跳过下载失败、损坏或空白的图片，保留作品在文字列表中的原序号；例如第 2 张封面失败，拼图中的编号为 1、3，仍可用 `看本 2` 获取该作品。该站没有可用封面时只展示文字列表。

### 单站指令

把“本子 / 里番”换成站点标识：

| 源站 | 标识 | 指令 |
|------|------|------|
| E-Hentai | `eh`（`ex`） | `搜eh`、`排行eh`、`随机eh`、`看eh`、`详情eh` |
| nhentai | `nh` | `搜nh`、`排行nh`、`随机nh`、`看nh`、`详情nh` |
| JMComic | `jm`（`禁漫`） | `搜jm`、`排行jm`、`随机jm`、`看jm`、`详情jm` |
| 哔咔 | `哔咔`（`pica`、`bika`） | `搜哔咔`、`排行哔咔`、`随机哔咔`、`看哔咔`、`详情哔咔` |
| Hanime1 | `anime`（`hanime`、`h1`） | `搜anime`、`排行anime`、`随机anime`、`看anime`、`详情anime` |

参数与聚合指令相同；`看<标识> ID|链接` 下载并发送文件，`详情<标识> ID|链接` 只看作品信息，例如 `看jm 350234`、`详情nh 177013`。

### 通用指令

|------|------|------|

| `看本 序号\|链接` | `本子下载`、`看里番` | 按最近列表的序号或作品链接 / `JM123456` 直接下载并发送文件 |

| `本子推送 [执行 序号]` | | 查看 / 手动执行推送任务（管理员） |

### 自定义触发词

**指令触发词** 默认收起，需要修改时打开“展开触发词设置”，即可统一展开所有操作；关闭后仍保留已填写的词并正常生效。

在插件配置的 **指令触发词** 中，每项填写一个词。例如把“全部本子搜索”填写为 `找本子`、`搜本子`、`搜本`，这三个词都能执行搜索，帮助优先展示 `找本子`。修改后会替换该操作的默认词；想继续使用某个默认词时，把它也保留在列表内。

触发词不能含空格或自带 `/` 等唤醒前缀；同项重复词会去重，空列表或全无效项会回退默认。不同操作使用同一个词时，冲突项回退默认并记录原因；自定义词与其他插件指令冲突时也会回退。停用操作请使用 AstrBot WebUI 指令管理，清空列表不会停用。帮助实时读取 WebUI 改名和禁用状态，结果提示也会跟随当前可用指令。

`看本`、`看eh`、`看jm` 等下载指令直接发送文件；查看封面与作品信息请用 `本子详情` 或对应站点的详情指令。下载与打包的详细进度默认关闭，可在“基础设置 → 发送进度提示”中开启；请求超过 3 秒仍会发送一次等待通知，无需重复发送。下载失败、缺页、页数限制提醒和仅链接模式的视频地址不受详细进度开关影响。

单次下载失败会给出重新获取的指令。随机或解析多部作品时，文件冷却按整次请求检查；某部文件失败会继续处理其他作品，并在最后汇总失败项和重试指令。自动解析时某张卡片发送失败，也会继续解析其他链接和获取已解析作品的文件。随机数量不足时会说明实际取得的数量及原因。

### 条件写法

| 写法 | 含义 | 生效源站 |
|------|------|----------|
| `p2`、`第2页`、`页码=2` | 页码 | 全部 |
| `排序=最新\|热门\|观看\|点赞` | 排序 | nhentai、JM、哔咔、Hanime1 |
| `评分=4` | 最低评分（2-5） | E-Hentai |
| `页数=20` | 最少页数 | E-Hentai、nhentai |
| `分类=同人志` | 分类 / 类型 | 全部（取值见下） |
| `-ntr` | 排除关键词 | 全部 |
| `3本` | 随机数量 | 随机指令 |

分类取值：E-Hentai 为 `同人志 / 漫画 / 画师CG / 游戏CG / 图集 / Cosplay / 西方 / 非H / 杂项`（也可写英文名）；JM 为 `同人 / 单本 / 短篇 / 韩漫 / 美漫 / cosplay / 3d / 其他`；Hanime1 为 `裏番 / 泡麵番 / 3DCG / Motion Anime / 2.5D / 2D動畫 / MMD / Cosplay`；哔咔为站内分类名；nhentai 为 `doujinshi / manga`。

JM 可按关键词搜索或只选分类；移动端接口不支持同时指定关键词与分类，插件会明确提示拆开查询。JM 分类列表的排除词按本页标题、作者和标签过滤。

带空格的条件值可使用引号，例如 `分类="Motion Anime"`；`分类=Motion Anime` 也能识别。源站标签语法中的引号会保留，例如 `female:"big breasts"`。页码必须为正整数，随机数量为 1-5；非法数值、未知排序、错误榜单或不完整引号会直接提示修正。`3本`、`数量=3` 仅用于随机，搜索时请用翻页查看更多结果。排行榜只接受榜单和页码；源站不支持某个条件时，结果会附上说明。

## 配置说明

所有配置都在 AstrBot WebUI 的插件配置页完成，分组如下（详见 [配置说明](docs/CONFIG.md)）：

- **基础设置**：自动解析、JM 编号识别、解析后动作（发送文件 / 仅信息）、进度提示。
- **指令触发词**：38 个操作各自的触发词列表，第一项用于帮助与操作提示。
- **源站开关**：逐个启用源站。
- **网络设置**：代理、超时、重试、图片并发。
- **各源站设置**：ExHentai Cookie、nhentai 语言过滤、JM 域名、哔咔账号、Hanime1 清晰度与发送方式。
- **文件输出**：PDF / ZIP / 两者，单 PDF 页数、图片质量与宽度、单本最大页数。
- **消息展示**：封面、封面模糊、列表拼图、合并转发与嵌套合并转发、单站 / 聚合列表条数、标签数。
- **随机设置**：随机后是否直接发送文件、聚合随机方式（混合随机 / 每站随机）、随机候选源站。
- **自动推送**：推送任务（排行榜 / 条件作品 / 随机作品）。
- **权限控制 / 缓存设置 / 使用限制**。

### 自动推送

在 **自动推送 → 推送任务** 点击添加，选择模板：

- **排行榜推送**：如“每天 09:00 推送 E-Hentai 日榜前 5”。
- **条件作品推送**：如“每天 20:00 搜索 `artist:xxx` 的最新作品”，开启“跳过已推送的作品”即为追更。
- **随机作品推送**：如“每天 12:00 随机 1 部”。

推送目标可填 **群号 / 用户 QQ**（使用“推送平台 ID”或自动选择的 QQ 平台），也可在目标会话发送 `本子会话` 获取会话 ID 填入“推送会话 ID”。配置完成后管理员先发送 `本子推送` 查看可执行任务编号，再发送 `本子推送 执行 1` 立即测试。停用、未知模板或无有效时间的配置会单独列出原因，不占用执行编号。

推送卡片附有作品的获取指令，可直接复制。开启“同时发送文件”后，某部下载或发送失败会继续处理其他作品，并向接收者汇总失败项和重试指令；管理员结果分别显示卡片成功会话数、文件成功与失败次数。随机请求全部失败会报告获取失败，不会显示成“没有新作品”。

去重按任务和接收目标分别记录：只推信息时以卡片发送成功为准，同时发文件时还要求文件或视频链接发送成功且没有下载缺页。部分目标失败后，仅向未完成的目标重试；缺页作品再次选中时会重新获取，配置页数上限造成的截断不算下载缺页。相同类型的任务必须使用不同名称，同一任务的并发执行会排队。按间隔推送支持 1–1440 分钟，每天零点重新计算。获取指令全部停用时，失败说明会引导联系管理员启用。

## 注意事项

- **E-Hentai** 请求过快会被临时封禁 IP，图片额度用尽会返回 509；遇到时请降低并发或稍后再试。
- **哔咔** 所有接口都需要登录，建议使用小号。
- **Hanime1** 视频较大，QQ 对视频 / 文件有大小限制；建议设置“视频大小上限”，或改用“文件”“仅链接”。
- 单站列表每页最多显示“单站列表最多显示条数”条，聚合列表每站最多显示“聚合列表每站最多显示条数”条；翻页按源站分页进行。
- 聚合指令需要等待所有源站返回（单站最长 90 秒），某个站失败或超时只在总览中标注，不影响其他站。部分源站失败时无法确认整体末页，仍保留下一页操作；只有全部参与源站都确认没有下一页时才提示最后一页。
- 合并转发仅在 QQ 个人号协议端（aiocqhttp）生效，其余平台逐条发送。嵌套合并转发显示异常时可关闭“聚合结果使用嵌套合并转发”。
- 已生成文件默认保留 24 小时供重复请求复用，可在“缓存设置”调整。下载缺页时再次发送同一指令会重新下载；因页数上限截断的文件可以复用，提高上限后会重新生成。
