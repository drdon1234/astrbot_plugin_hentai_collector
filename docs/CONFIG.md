# 配置说明

所有配置都在 AstrBot WebUI → 插件 → 本插件 → 配置页完成，保存后插件自动重载。配置值会经过 `core/config_manager.py` 的类型转换与范围限制，填错时回退默认值，不会导致插件无法加载。

## 基础设置 `basic`

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 自动解析作品链接 `auto_parse` | 开启 | 消息中出现支持的作品链接时自动处理；以本插件指令开头的消息不会被重复解析 |
| 识别 JM 编号 `parse_jm_code` | 开启 | `JM123456`、`jm 123456` 也会被自动解析；纯数字不识别 |
| 解析链接后的动作 `link_action` | 发送信息和文件 | 选“仅发送信息”时只发封面与信息，用户再用 `看本` 获取 |
| 默认源站 `default_source` | E-Hentai | 指令没有写源站时使用；未启用时回退第一个已启用源站 |
| 发送进度提示 `send_progress` | 开启 | 下载与打包过程中的提示消息 |

## 源站开关 `sources`

逐个启用 E-Hentai、nhentai、JMComic、哔咔、Hanime1。哔咔默认关闭，填写账号后再开启。启用但不可用（缺账号、缺依赖）的源站会在 `本子帮助` 中标注原因。

## 网络设置 `network`

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 代理地址 `proxy` | 空 | `http://`、`https://` 或 `socks5://`；Docker 中填宿主机局域网 IP |
| 请求超时 `timeout` | 30 | 秒，5-300 |
| 失败重试次数 `retries` | 3 | 0-10，网络错误与 429/5xx 会指数退避重试 |
| 图片下载并发数 `image_concurrency` | 8 | 1-32，单本同时下载的图片数 |

各源站的“使用代理”开关决定该源站是否使用这里的代理地址；代理地址为空时开关无效。

## 源站设置

### E-Hentai `ehentai`

| 配置项 | 说明 |
|--------|------|
| 站点 `site` | `e-hentai`（表站）或 `exhentai`（里站） |
| Cookie `ipb_member_id` / `ipb_pass_hash` / `igneous` | 里站必填，缺任一项自动回退表站并记录警告 |
| 使用代理 `use_proxy` | 默认开启 |
| 请求间隔 `request_interval` | 默认 0.5 秒，过小可能被临时封禁 IP |

### nhentai `nhentai`

| 配置项 | 说明 |
|--------|------|
| 语言过滤 `language` | 不限 / 中文 / 英文 / 日文，作用于搜索、排行、随机 |
| 使用代理 `use_proxy` | 默认开启 |

### JMComic `jmcomic`

| 配置项 | 说明 |
|--------|------|
| 使用代理 `use_proxy` | 默认关闭（移动端 API 国内通常可直连） |
| API 域名 `domains` | 留空使用 jmcomic 内置域名，全部失效时手动填写 |
| 图片下载线程数 `image_threads` | 1-32 |

### 哔咔 `pica`

| 配置项 | 说明 |
|--------|------|
| 账号 `email` / 密码 `password` | 必填；登录 Token 保存在插件数据目录 `runtime/pica_token.json` |
| 图片质量 `image_quality` | original / high / medium / low |
| 使用代理 `use_proxy` | 默认开启 |

### Hanime1 `hanime1`

| 配置项 | 说明 |
|--------|------|
| 默认类型 `default_genre` | 搜索、排行、随机未写“分类=”时使用，默认 `裏番` |
| 目标清晰度 `quality` | 选择不超过该值的最高清晰度 |
| 发送方式 `send_mode` | 视频 / 文件 / 仅链接（不下载，发送有时效的直链） |
| 视频大小上限 `max_size_mb` | 超过时放弃下载，0 为不限制 |
| Cookie `cookie` | 可选，填写后可能获得更高清晰度 |
| 使用代理 `use_proxy` | 默认开启 |

## 文件输出 `output`

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 输出格式 `format` | PDF | PDF / ZIP / PDF+ZIP；ZIP 内为原图 |
| 单本最多下载页数 `max_pages` | 0 | 0 为不限制；JM 会整本下载后截取 |
| 单个 PDF 最大页数 `max_pages_per_pdf` | 200 | 超过时拆分为 `标题-1.pdf`、`标题-2.pdf` |
| PDF 图片质量 `pdf_quality` | 85 | JPEG 质量 1-100 |
| PDF 图片最大宽度 `pdf_max_width` | 1600 | 0 为不缩放 |

修改以上参数后，旧缓存会因参数指纹不同而自动失效。

## 消息展示 `display`

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 发送封面 `show_cover` | 开启 | 作品信息与列表附带封面 |
| 封面模糊程度 `cover_blur` | 0 | 高斯模糊半径 0-50 |
| 列表封面拼图 `search_cover_grid` | 开启 | 列表附带带序号的封面拼图 |
| 使用合并转发 `use_forward` | 开启 | 仅 aiocqhttp 生效 |
| 列表最多显示条数 `list_size` | 20 | 1-50 |
| 最多显示标签数 `max_tags` | 12 | 0 为不显示 |
| 显示简介 `show_description` | 开启 | 简介超过 200 字截断 |

## 随机设置 `random`

| 配置项 | 说明 |
|--------|------|
| 随机后直接发送文件 `auto_fetch` | 默认关闭，只发作品信息 |
| 全随机候选源站 `pool` | `随机本子` 不写源站、或推送任务源站为“全部”时的候选；默认 E-Hentai、nhentai、JMComic |

## 自动推送 `push`

| 配置项 | 说明 |
|--------|------|
| 启用自动推送 `enable` | 关闭时任务不会定时执行，但管理员仍可 `本子推送 执行 序号` 手动执行 |
| 推送平台 ID `platform_id` | 群号 / 用户 ID 所属的平台适配器；留空自动选择第一个 aiocqhttp 平台 |
| 推送任务 `tasks` | 模板列表，见下 |

三种任务模板的公共字段：

| 字段 | 说明 |
|------|------|
| 启用 | 停用的任务不会被调度 |
| 任务名称 | 显示在推送标题中，同时是去重记录的标识（改名后去重记录重新开始） |
| 推送时间 | `HH:MM` 列表，每天在这些时间推送 |
| 推送间隔（分钟） | 大于 0 时忽略推送时间，从每天 00:00 起按间隔推送 |
| 推送群号 / 推送用户 / 推送会话 ID | 推送目标，可同时填写 |
| 同时发送文件 | 推送作品信息后继续下载并发送文件（耗时较长） |
| 跳过已推送的作品 | 去重记录保存在插件数据目录 `push_history.json` |

模板专属字段：

- **排行榜推送**：源站、榜单、推送数量。
- **条件作品推送**：源站、关键词、分类、排序、最低评分、最少页数、推送数量。
- **随机作品推送**：源站（可选“全部”）、关键词、分类、推送数量。

## 权限控制 `permission`

与 media_parser 一致：管理员 > 个人白名单 > 个人黑名单 > 群白名单 > 群黑名单；开启白名单后未命中的会话全部拒绝。配置类型错误时整段权限 fail-closed（拒绝所有消息）。管理员 ID 自动加入个人白名单。

## 缓存设置 `cache`

| 配置项 | 说明 |
|--------|------|
| 缓存目录 `cache_dir` | 留空：普通部署为 `data/plugin_data/astrbot_plugin_hentai_collector/cache`，Docker 为 `/app/sharedFolder/astrbot_plugin_hentai_collector/cache` |
| 已生成文件保留时长 `keep_hours` | 默认 24 小时；保留期内重复请求同一作品直接复用文件；0 表示约 5 分钟后清理 |

插件每 30 分钟清理一次过期任务目录，只删除带插件归属标记的目录。

## 使用限制 `limits`

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 同时处理作品数 `max_concurrent_jobs` | 2 | 同一作品的并发请求会排队并复用结果 |
| 获取文件冷却 `user_cooldown_seconds` | 0 | 同一用户两次获取文件的最小间隔，管理员不受限 |
| 搜索结果有效期 `session_minutes` | 30 | 超时后需重新搜索 |
