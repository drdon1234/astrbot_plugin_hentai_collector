# 配置说明

所有配置都在 AstrBot WebUI → 插件 → 本插件 → 配置页完成，保存后插件自动重载。配置值会经过 `core/config_manager.py` 的类型转换与范围限制，填错时回退默认值，不会导致插件无法加载。

文中的指令示例使用默认触发词。配置自定义触发词或在 AstrBot 指令管理中改名后，以实际帮助和结果提示中的指令为准。

## 基础设置 `basic`

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 自动解析作品链接 `auto_parse` | 开启 | 消息中出现支持的作品链接时自动处理；以本插件指令开头的消息不会被重复解析 |
| 识别 JM 编号 `parse_jm_code` | 开启 | `JM123456`、`jm 123456` 也会被自动解析；纯数字不识别 |
| 解析链接后的动作 `link_action` | 发送信息和文件 | 选“仅发送信息”时只发封面与信息；获取文件请复制卡片中的获取指令，或使用获取指令加原链接，解析卡片不建立列表序号 |
| 发送进度提示 `send_progress` | 关闭 | 开启后发送下载与打包的详细进度；请求超过 3 秒的一次等待通知，以及失败、缺页、截断和视频链接说明，不受此开关影响 |

重复词保留第一项，无效项被忽略；空列表、全部无效或类型错误时回退该操作默认词。不同操作使用相同词时，相关配置回退默认并记录日志；新增自定义词与其他插件指令冲突时也会回退。清空列表不会禁用操作，停用请使用 AstrBot 指令管理。

插件配置应用后会继续载入 AstrBot WebUI 已保存的改名、别名及禁用状态，因此 **WebUI 指令管理优先**。帮助和操作提示实时读取当前状态，禁用操作不会继续出现在可执行提示中；若修改插件配置后仍显示另一个名称，请检查 WebUI 指令管理中的覆盖设置。

## 源站开关 `sources`

逐个启用 E-Hentai、nhentai、JMComic、哔咔、Hanime1。哔咔默认关闭，填写账号后再开启。启用但不可用（缺账号、缺依赖）的源站会在 `本子帮助` 中标注原因。

## 网络设置 `network`

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 代理地址 `proxy` | 空 | `http://`、`https://` 或 `socks5://`；Docker 中填宿主机局域网 IP |
| 请求超时 `timeout` | 30 | 秒，5-300 |
| 失败重试次数 `retries` | 3 | 0-10，网络错误与 429/5xx 会指数退避重试 |
| 图片下载并发数 `image_concurrency` | 8 | 1-32，单本同时下载的图片数 |

各源站的“使用代理”开关决定该源站是否使用这里的代理地址；代理地址为空时开关无效。

## 源站设置

### E-Hentai `ehentai`

| 配置项 | 说明 |
|--------|------|
| 站点 `site` | `e-hentai`（表站）或 `exhentai`（里站） |
| Cookie `ipb_member_id` / `ipb_pass_hash` / `igneous` | 里站必填，缺任一项自动回退表站并记录警告；只发送到所选站点的 HTTPS 主机，不发送到异域图片节点 |
| 使用代理 `use_proxy` | 默认开启 |
| 请求间隔 `request_interval` | 默认 0.5 秒。每下载一页都要请求一次单页，整本耗时约为“页数 × 间隔”；过小可能被临时封禁 IP |

## 文件输出 `output`

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 输出格式 `format` | PDF | PDF / ZIP / PDF+ZIP；ZIP 内为原图 |
| 单本最多下载页数 `max_pages` | 0 | 0 为不限制；在图片列表发现和实际下载前限制页数，JM 同样只下载所需章节中的前若干页 |
| 单个 PDF 最大页数 `max_pages_per_pdf` | 200 | 超过时拆分为 `标题-1.pdf`、`标题-2.pdf` |
| PDF 图片质量 `pdf_quality` | 85 | JPEG 质量 1-100 |
| PDF 图片最大宽度 `pdf_max_width` | 1600 | 0 为不缩放 |

修改以上参数后，旧缓存会因参数指纹不同而自动失效。

## 随机设置 `random`

| 配置项 | 说明 |
|--------|------|
| 随机后直接发送文件 `auto_fetch` | 默认关闭，只发作品信息；获取文件请复制卡片中的获取指令。随机结果不建立搜索序号，不能用 `看本 1` 指向刚随机出的第一部 |
| 聚合随机方式 `mode` | 不带站点的 `随机本子` / `随机里番`：**混合随机**（默认）每次从候选源站中随机挑一个站，共 N 部；**每站随机**为每个候选源站各随机 N 部，按源站分组发送。`随机eh` 等站点指令只从该站随机 |
| 随机候选源站 `pool` | 聚合随机与源站为“全部”的随机推送的候选；默认 E-Hentai、nhentai、JMComic、Hanime1。勾选的源站中没有对应类型（本子 / 里番）时使用该类型的全部可用源站 |

## 自动推送 `push`

| 配置项 | 说明 |
|--------|------|
| 启用自动推送 `enable` | 关闭时任务不会定时执行，但管理员仍可 `本子推送 执行 序号` 手动执行 |
| 推送平台 ID `platform_id` | 群号 / 用户 ID 所属的平台适配器；留空自动选择第一个 aiocqhttp 平台 |
| 推送任务 `tasks` | 模板列表，见下 |

三种任务模板的公共字段：

| 字段 | 说明 |
|------|------|
| 启用 | 停用的任务不会被调度 |
| 任务名称 | 显示在推送标题中，同类型任务的名称必须唯一；改名后去重记录重新开始 |
| 推送时间 | `HH:MM` 列表，每天在这些时间推送 |
| 推送间隔（分钟） | 0 使用推送时间；1–1440 忽略推送时间，从每天 00:00 起重新按间隔推送；超过一天的值无效 |
| 推送群号 / 推送用户 / 推送会话 ID | 推送目标，可同时填写 |
| 同时发送文件 | 推送作品信息后继续下载并发送文件（耗时较长）；某部失败后继续其他作品，并汇总失败原因及重试指令 |
| 跳过已推送的作品 | 去重记录保存在插件数据目录 `push_history.json`；按任务和目标分别记录已完成作品，失败目标单独重试 |

模板专属字段：

- **排行榜推送**：源站、榜单、推送数量。
- **条件作品推送**：源站、关键词、分类、排序、最低评分、最少页数、推送数量。
- **随机作品推送**：源站（可选“全部”）、关键词、分类、推送数量。

管理员发送 `本子推送` 查看任务状态和可执行编号，再用 `本子推送 执行 1` 手动执行。停用、未知模板、没有有效时间的配置会显示原因及原配置位置，不占用执行编号。失败作品附当前可用的重新获取指令；如果获取操作全部停用，则提示联系管理员启用。

随机请求全部失败会报告“获取作品失败”；只取得已推送作品时显示“没有新作品”，搜索或排行返回空列表时显示“没有符合条件的作品”。数量不足会说明实际数量与原因。手动执行结果分别统计卡片成功会话数、文件成功和失败次数；下载缺页计入文件失败，接收者会看到缺页数量。文件次数按“作品 × 目标”计算，某作品拆成多个文件时仍算一次获取投递。

仅推作品信息时，目标收到卡片即为该目标记录完成；开启“同时发送文件”后，还要求文件或视频链接发送成功且没有下载缺页。失败目标保留后续入选资格，成功目标不重复投递；因 `output.max_pages` 截断而没有缺页的文件仍算完成。同一任务的手动与定时执行串行，后出现的同类型同名配置会显示冲突原因。旧任务级历史首次加载时一次性完整归档到 `migrated_records` 中用于追溯，不据此推断任何目标已完成；未知完成状态的目标首次执行可能重新收到作品，之后按目标分别去重。推送卡片上的获取指令不依赖搜索会话，可直接复制获取。

## 权限控制 `permission`

与 media_parser 一致：管理员 > 个人白名单 > 个人黑名单 > 群白名单 > 群黑名单；开启白名单后未命中的会话全部拒绝。配置类型错误时整段权限 fail-closed（拒绝所有消息）。管理员 ID 自动加入个人白名单。

## 缓存设置 `cache`

| 配置项 | 说明 |
|--------|------|
| 缓存目录 `cache_dir` | 留空：普通部署为 `data/plugin_data/astrbot_plugin_hentai_collector/cache`，Docker 为 `/app/sharedFolder/astrbot_plugin_hentai_collector/cache` |
| 已生成文件保留时长 `keep_hours` | 默认 24 小时；保留期内重复请求可复用完整文件；下载缺页时下次同指令重新下载；0 表示约 5 分钟后清理 |

因 `output.max_pages` 截断的缓存可以复用，提示会明确区分截断与下载缺页；提高页数上限后，参数指纹变化会使旧缓存失效。插件每 30 分钟清理一次过期任务目录，只删除带插件归属标记的目录。

## 使用限制 `limits`

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 同时处理作品数 `max_concurrent_jobs` | 2 | 同一作品的并发请求会排队并复用结果 |
| 获取文件冷却 `user_cooldown_seconds` | 0 | 同一用户两次获取文件请求的最小间隔，管理员不受限；随机或解析多部作品时按整次请求检查一次 |
| 搜索结果有效期 `session_minutes` | 30 | 序号只属于本人在当前聊天中最近一次搜索或排行；超时或插件重载后需重新查询，随机和解析卡片不建立序号 |

列表成功发送后才替换会话；新搜索成功但无匹配结果时，空结果通知发送成功后才清除旧序号。查询全部失败、翻页失败或通知发送失败会保留原列表。来自同一用户、同一聊天的列表请求串行执行；按序号选择也会等待列表展示提交完成，选定作品后即释放等待，不阻塞后续查询。聚合列表存在失败源站时仍允许尝试下一页，不提前判定最后一页。
